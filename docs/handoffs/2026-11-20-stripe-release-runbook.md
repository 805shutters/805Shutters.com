## Implemented locally

- Provider selection defaults to Square. Stripe requires matching account/environment, enabled collection flag, server credentials and production-only live mode. No fallback to another processor after a Stripe failure.
- Exact quote or imported-entry/job requests with integer cents, current combined ledger, signed selected contracts, immutable request identity, provider idempotency, one collectible request per target and reviewed historical Square clearance. Imported entries resolve and validate the linked job. No arbitrary name/amount matching.
- Hosted Checkout redirects; old route aliases dispatch through the selected provider. The Square wallet API is blocked in Stripe mode; Square browser wallet components are omitted. Existing public contract URLs remain stable.
- Additive service-only Stripe request, event, object, allocation, clearance, bank-match, recovery, delivery and owner-alert tables. Migration applied to dedicated805 and service-only grants verified. Existing Square payments retain their identities.
- Gross successful live payments allocate once to the existing ledger. Wrong account/mode/currency/amount, late balance conflicts, refunds and disputes hold for review. Payment does not sign, cancel or complete jobs. Allocated ledger identities cannot be silently edited/deleted.
- Durable raw-signature webhook intake before acknowledgement, authoritative Stripe retrieval, polling/backfill cursors, lease and independent recovery phases. A failed phase retains its cursor while later evidence can recover. Successful checkpoints do not certify all records reconciled.
- Durable email/SMS submission records hold ambiguous acknowledgements rather than resending. Existing mobile request keys and installment notification records remain. Accepted is not delivered or paid.
- Installments remember their original provider. After provider cutover, old-provider links are held from new delivery until reviewed/retired; recovery for retirement still uses the original identity. New saved-card enrollment is blocked in Stripe mode. Existing mandates are not migrated or reauthorized automatically.
- The old reminder route no longer charges cards. A separate POST charge route requires an explicit secret and `LEGACY_SQUARE_AUTOPAY_ENABLED=true`; no schedule was added for it. Existing external callers must be inventoried before release because this changes their behavior.
- Payment Hub merges Stripe and Square using exact allocation identities without hiding same-amount manual receipts. Dedicated Stripe finance view separates requests, processor records, fees, refunds/disputes, payout contents, owner alerts and explicit Mercury bank matches. GET does not synchronize or mutate. Owner-only POST performs review actions.
- Automatic payout contents reconcile balance transactions against the exact net amount. Manual payouts require statement review. Positive and negative payout bank matches require exact unique transaction evidence. Payouts and transfers never create sales income. The visible-evidence CSV is capped/scoped, not a complete account report.

Stripe's automatic payout transaction filter does not establish manual-payout composition: [Stripe payout guidance](https://support.stripe.com/questions/find-what-transactions-were-included-in-or-impacted-a-payout-amount?locale=en-GB). Negative bank debits can arise from negative Stripe balances: [Stripe negative-balance guidance](https://support.stripe.com/questions/fix-the-negative-balance-on-your-account?locale=en-GB).
