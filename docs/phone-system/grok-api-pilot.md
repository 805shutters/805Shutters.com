# Grok media receptionist

The live answer path is Twilio Media Streams to the Grok Voice API (`grok-voice-3.0`). Hosted SIP and ConversationRelay are not used for this flow.

1. Twilio answers onto the Grok media stream and rings the incoming list at the same time. There is no customer ring tone. The listening welcome is exactly: "Thank you for calling 805 Shutters. We appreciate you supporting local business. Let me reach out to a team member to connect you with. I can also help you schedule an appointment. We offer free in-home consultations, whether you're exploring shutters, blinds, or shades, to help you find the right light control, privacy, and style." A human answer interrupts that welcome and connects. The caller can choose scheduling before the welcome finishes. That choice stores phase `message` so the existing scheduling route can search and prepare, and it leaves the original staff offer ringing. The audio cache is still rendered with `POST https://api.x.ai/v1/tts` (`voice_id` `ara`, `language` `en`, wav at 8000 Hz) for the unavailable and voicemail lines. A live response is PCM 16-bit mono at 8000 Hz with a streaming header (RIFF size `0x80000023`, data size `0x7fffffff`); both sizes are rewritten from the file length before the wav is stored in the private `voice-805-prompts` bucket as `ara-{name}-{text hash}.wav` and served from `/twilio/prompts/{name}-{text hash}.wav` through `<Play>`. `<Say>` is used only when that audio is not available yet. The same cache covers the unavailable line and the voicemail prompt. A changed prompt gets a new object key and a new public path, so Twilio cannot keep the previous recording at the old URL. The unversioned `/twilio/prompts/{name}.wav` path still serves the current audio and is not cached for a day. The customer conference wait is silence, not a ringing tone.
2. The incoming ring list starts when the call is answered, in parallel with that greeting, for `VOICE_805_OFFER_SECONDS` (default 20). Unset, `VOICE_805_RING_STAFF_JSON` is `["mike","jessica"]`. A nonempty subset such as `["mike"]` rings only those people. An empty or invalid value fails closed and does not add Jessica. On 2026-10-25 the live secret was restored to `["mike","jessica"]` from the dashboard, and `/health` reported that list. Do not change the secret from this branch. The offer window is not extended by the greeting. Each leg uses `MachineDetection=Enable` and async AMD. Only `AnsweredBy=human` bridges. Machine, beep, silence, fax, and unknown results hang up that leg. One finished leg is enough when it is the only leg. A human answer redirects the caller immediately, including while the welcome is still playing. Callback, consult, message notices, and the booking SMS to `JESSICA_805_SALES_SMS_NUMBER` and `MIKE_805_SALES_SMS_NUMBER` still include both people.
3. The caller is connected to `wss://{origin}/twilio/media/{call id}` at answer, while staff are still ringing. The socket load and the first greeting decision read the call row. They do not commit it. A claim whose write has already stored the stream id can continue into the greeting, but only if the session is still open when that read returns. A later missed read closes the session and requests voicemail fallback instead of waiting out the media limit, and it does not reuse the call from socket attach. A call row that is already gone closes without that fallback. An owned, ended, or handoff call is not given the no-answer close. If nobody answers, Grok speaks that close once and offers a message or an appointment without repeating the welcome. The WebSocket is authorized with the Twilio signature on that `wss` URL, the same URL with the documented trailing slash, or the `https` form of that public path. A gateway rewrite of the request path does not change the signed URL. The API key is not in the URL. `<Stream statusCallback>` records a sanitized `StreamError` if the socket does not attach.
4. Grok's no-answer close is spoken once, exactly: "Thanks for waiting. Our team members are tied up at the moment. I can take a message and have someone call you back, or I can help you schedule an appointment. Which would you like?" It does not repeat the thank-you greeting, it does not improvise an apology, and it does not say the team is with other customers. A message collects one answer at a time: name, confirmation of a valid caller ID, then the reason. A blocked or caller-changed number is still collected. The spoken reason is the transcript. No new call or voicemail audio is recorded. The transcript is stored on a CRM callback item with status needs_callback, matched to an existing customer by that phone when there is one. A pending text of that transcript is queued for both Mike and Jessica. An unconfirmed transcript keeps UNCONFIRMED and the STOP footer outside the shortened message text. Those texts are not sent while campaign `BU542a67b844388f5192a84c79d6a86cb9` is draft. A caller reply that arrives during opening or question playback is kept and applied before the Twilio playback mark. A yes spoken before that readback has played does not book. The message is read back and saved only after a spoken yes. An appointment is collected one question at a time. Each answer is stored on the call before the next question. A weekday is recorded before asking the time, and a volunteered "Friday anytime" is recorded without demanding a clock time. The full street address is one question, then it is read back until the caller confirms it. City, home or commercial, a commercial window count, and name are separate questions only when they are still missing. A valid caller ID is the callback number and is not requested again; caller ID does not verify identity. Before the address and travel check are finished, the caller hears that the time will be checked, not that it is confirmed. The server recommends one verified slot by the smallest proved incremental detour, which is the new neighbor legs minus the removed previous-to-next baseline, then the tighter proved gap after the 15-minute buffer, then earlier date and time. It offers and books only a currently open published CRM slot. If no open CRM time fits, it offers a callback so staff can see whether they can accommodate it. "Absolutely, we're confirmed" is spoken only after the calendar save is verified. Residential visits remain 60 minutes. Commercial visits remain 60, 120, or 180 minutes from the window count. A question about length is answered "Generally about one hour." The booking authorization gate is unchanged. If that gate is off, the request is saved as a callback item noting they want an appointment. A failed voice session or CRM write says the call could not continue and that no recording was made, then hangs up. If a written message was already saved, it says that text is saved and that no recording was made. That failure does not drop the written message or its queued staff notices. Historical recording URLs stay on old callback rows.
5. A save happens only after the exact readback has played and the caller says yes. Ambiguous speech, silence, interruption, or a correction does not save. Appointments commit through `voice_805_book_confirmed` only when `VOICE_805_BOOKING_AUTHORIZED=true` and the dataset is production. The calendar row is verified, including the agent source note, before the caller is told it is booked. The same transaction queues one SMS each for Jessica and Mike at `JESSICA_805_SALES_SMS_NUMBER` and `MIKE_805_SALES_SMS_NUMBER`. Those rows start pending. They send only through the dedicated 805 staff SMS account, service `MG60d4038bf54bffa0690cce85a6e49147`, and from number `+18055908050`, and they fail closed when that configuration is missing. They do not use the shared MTS campaign or +18057931853. Each text ends with “Reply STOP to unsubscribe; HELP for help.” Provider acceptance and handset delivery are recorded separately: `queued` or `accepted` is not `delivered`. A failed or uncertain send is not retried automatically. Booking-alert SMS is not activated by the caller-message transcript work, and its four website variables stay unset. Transcript notices use purpose `transcript`, stay `pending`, and the voice worker does not submit them. `transcriptSmsSendingEnabled()` is false. Pending is not delivered. See `docs/phone-system/staff-booking-sms.md`. Customer email and SMS are not added. Messages are verified in `crm_callback_items`. When the call has a customer id, `voice_805_save_summary` writes one factual `crm_activity_events` row for that customer and, when exactly one non-deleted job has that normalized caller phone and a contract or product for that same customer, for that job. A job that only shares the phone is not attached. Migration `supabase/migrations/20261025194500_voice_805_call_summaries.sql` is not applied. No summary is written without a customer id. If the stream detached, the summary states that the staff takeover portion cannot be summarized.
6. If the media stream does not attach, or Grok fails, the Edge fallback says the call could not continue and that no recording was made, then hangs up. It does not repeat the thank-you greeting and does not offer a spoken choice. `<Say>` remains the fallback until the versioned wav is stored. The dedicated number's live backup is still the Twilio Function at `https://voice-805-fallback-9089-prod.twil.io/fallback` (service `ZS85a203f4cf8accf080ac48195e3801ed`, number `PNaafffce88dd92efd78345e2967637931`). A read-only GET of that URL still returns `<Response><Record maxLength="120" playBeep="true" timeout="5"/><Hangup/></Response>`. The reviewed replacement is `services/voice-805/twilio-fallback/fallback.js`. Do not deploy that function from this branch. The Pro Edge worker wall clock is 400 seconds. The media socket stops at 270 seconds, before that limit and before the 5-minute call watchdog, so the state write and voicemail fallback can finish. A stopped stream is not a booked appointment.

The realtime socket stays `wss://api.x.ai/v1/realtime?model=grok-voice-3.0` with session voice `ara` and G.711 `audio/pcmu`. Caller audio is transcribed with `audio.input.transcription.model` set to `grok-transcribe`. Final caller text is taken from `conversation.item.input_audio_transcription.completed` or a completed `conversation.item.added` user item. A scripted line is the documented `force_message` lifecycle (`response.created`, `response.output_audio.delta`, `response.done`) and does not wait for an output transcript. An automatic response that was already open, or one the server marks cancelled, does not play or advance that line. If that automatic response and the scripted line both finish as completed, neither is played. The same scripted line is sent once more. If that retry does not reach playback within 10 seconds, the call leaves the media socket instead of staying silent. After the audio is queued, the Twilio playback mark must arrive within the queued PCMU duration plus 5 seconds. A missing or unmatched mark uses the voicemail fallback and does not arm confirmation or save. Lifecycle logs include the opaque call id only. The media WebSocket is accepted before the call row is loaded, because the hosted gateway turns a non-101 response to an Upgrade request into HTTP 502. xAI's current voice docs list `grok-voice-3.0` as the flagship model (`grok-voice-latest` is only an alias) and document `POST /v1/tts` plus the `ara` voice. An unauthenticated `POST /v1/tts` and `GET /v1/realtime?model=grok-voice-3.0` both returned HTTP 401, so those paths exist. `VOICE_805_XAI_API_KEY` was not in this environment, so live synthesis and an authenticated realtime handshake were not run. `GET /v1/tts/voices` timed out without a status and was not treated as verified.

Suggested URLs after a future deploy, with `ORIGIN` equal to `VOICE_805_PUBLIC_ORIGIN`:

- Voice webhook: `POST {ORIGIN}/twilio/inbound`
- Status callback: `POST {ORIGIN}/twilio/status`
- Edge fallback: `POST {ORIGIN}/twilio/fallback.xml`. The dedicated number's configured backup is the separate Twilio Function documented above, and this branch does not change it.
