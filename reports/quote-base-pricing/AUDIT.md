September retail SHA-256: `3767de1e04ee7c8dc6bab14a6224868e4ca366f2ec4be2d8d3d13ec5cf45aafd`.

Current native technical limits take precedence over older local assumptions. In particular, SmartPrivacy uses its native net-size and area rules. A universal shutter maximum cannot be certified without panel/frame/application details; base price fixtures establish the configured selling arithmetic, not fabrication approval. Manufacturer pricing/assortment is grounded in the repository's pinned documents and saved portal evidence; no new vendor order was submitted.

## Implementation and preservation

- `base-configuration.ts` resolves typed defaults only on intentional creation/product/program selection. Metadata version `805-v2-base-1` lives in `options_json`. Fabric/color and installation fields remain blank.
- Native server recalculation, explicit Reprice and send preparation share `priceQuoteV2Selection`. Only versioned base selections waive precisely identified **missing non-pricing** issues. Unknown selected fabric, incompatible combinations, invalid sizes and incomplete paid upgrades remain blocked.
- Fabric selection persists its actual program/category labels; clearing restores the base program for the retained construction. Native price derivation rebuilds all option charges, avoiding stale/duplicate adders.
- Customer documents receive saved native snapshots and their existing totals. The added metadata is internal and does not insert assumption language or invented color/fabric selections.
- No load/mount defaulting effect, historical rewrite or automatic manual-price release was added. Existing native serialization, copy/revision controls and frozen snapshot protections remain in place.
- Browser fixtures use actual DesignCard, native server pricing/send preparation and the shared customer QuoteLineItemCard. Local test storage and an isolated local middleware perform no production writes or external sends.
